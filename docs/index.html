Two jobs, no compromises

Dock clicks make windows

Click a running app's Dock icon and it receives its own New Window command. Hold ⇧ — or any other modifier — for the Dock's normal behaviour. Folders, Trash, right-clicks and drags are left alone.

⌥Tab sees every window

One entry per on-screen window on the current Space, with titles. Tap Tab to cycle, arrows to move, release ⌥ to raise the exact window. Esc cancels. System ⌘Tab stays untouched.

Snapshots when you want them

An optional mode shows up to five large window cards with live thumbnails, app icons and titles. Captures start only after the switcher is on screen, so they never delay it.

Fast by construction

No window is created when you invoke it. One resident Metal surface is ordered in at launch and left at alpha zero, so revealing either overlay is an alpha flip — not a window, a layout pass, or a GPU wait.

  • A cached current-Space catalog. Window enumeration runs on a background queue and refreshes on app, launch and Space changes — opening the switcher just reads it.
  • No SwiftUI on the hot path. SwiftUI is only used for Settings and onboarding; overlays are a layer-hosting CAMetalLayer view.
  • Prewarmed Metal. Shaders, pipelines and text atlases are compiled at launch, so a Tab press only changes an index and submits one command buffer.
  • No app activation. A non-activating panel at pop-up menu level joins all Spaces and works over full-screen apps.
  • Idle means idle. The display link pauses whenever the overlay is hidden.

Snapshots, when you ask for them

Snapshot mode turns each entry into a card: a live thumbnail of the window, the app icon, the title, and a pixel-accurate rounded selection outline. It is optional. The compact icon row stays the default, so the switcher still opens instantly if Screen Recording hasn't been granted.

Documentation images use sample window content; the app captures the real windows on your Mac.

Install

  1. 1

    Download and unzip

    Grab the latest release, unzip it, and move New Window Plz.app into /Applications. Move it there before granting permissions so macOS remembers them.

  2. 2

    Launch and grant Accessibility

    The app lives in the menu bar. Choose Grant Accessibility Access, then enable New Window Plz in System Settings → Privacy & Security → Accessibility.

  3. 3

    Optionally allow snapshots

    Turn on Window switcher → Show window snapshots and grant Screen Recording when asked. Relaunch the app after granting it.

About macOS Gatekeeper

This build is ad-hoc signed but not notarized, so macOS warns the first time you open it. Right-click the app → Open, or clear the quarantine flag once:

xattr -dr com.apple.quarantine "/Applications/New Window Plz.app"

Building from source is equally supported and avoids the warning entirely — see the README.

Permissions, explained

Accessibility

Used to read the Dock, trigger the target app's own New Window command, intercept ⌥Tab, and raise a specific window by ID.

Screen Recording optional

Only when snapshots are enabled, and only to capture the visible windows listed in the switcher.

Nothing else

No network access, no analytics, no window contents otherwise. Settings and login-item state stay on your Mac.

Good to know

  • Only the active Space's on-screen windows are listed. Minimized windows and other Spaces are excluded by design.
  • Apps with neither a New Window menu item nor a ⌘N behaviour simply activate; they can't be made multi-window.
  • Secure input fields can keep global keyboard taps from seeing ⌥Tab.
  • Not sandboxed and not Mac App Store compatible — Accessibility event taps require it.
  • Rebuilding with a different ad-hoc signature may require re-granting permissions.
